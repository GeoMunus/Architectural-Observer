# Chronicler — AI Timeline Creator

Generates fictional histories you can extend, fork and rewrite. Point it at a
premise, pick a genre, and it produces a timeline of dated events with a
consistent cast of factions, figures, places, artifacts and forces — then lets
you edit every part of it.

Vanilla ES modules, no build step, no dependencies.

## Running it

The app uses ES modules, so it needs to be served over HTTP rather than opened
from the filesystem:

```sh
cd timeline
python3 -m http.server 8000
# then open http://localhost:8000/
```

`dist/chronicler.html` is a single self-contained file with everything inlined —
that one *can* be opened directly from disk or dropped on a static host. Rebuild
it after changing anything under `js/` or `style.css`:

```sh
node build.mjs
```

## Two ways to generate

**Built-in engine (default).** Everything runs locally: no network, no API key.
The same seed always produces the same history, so a timeline you like can be
reproduced or shared as a seed string.

**Claude.** Set *Generated by* to a Claude option and the model writes the
events instead, while the engine still builds the world and keeps the record
editable. Two backends are supported: a page-level `window.claude` runtime if
one is present, or your own Anthropic API key called directly from the browser.
If a model call fails, the app falls back to the local engine and says so.

An API key entered in the UI is stored in this browser's `localStorage` and sent
only to `api.anthropic.com`. Any script on the page can read it, so use a key
you are willing to rotate.

## How the engine works

The interesting part is that events are not drawn independently. The generator
holds a live model of the world and only fires events whose preconditions
currently hold, which is what makes the output read as a history rather than a
list of incidents.

| File | Role |
| --- | --- |
| `js/rng.js` | Seeded PRNG (mulberry32) plus weighted-pick helpers |
| `js/lexicon.js` | Per-genre word banks, phonetic palettes, the dramatic arc |
| `js/worldgen.js` | Premise parsing and cast construction |
| `js/beats.js` | ~35 beat templates: cast slots, preconditions, effects, prose |
| `js/generator.js` | The engine — act planning, cast binding, state replay |
| `js/ai.js` | Optional Claude backends and output reconciliation |
| `js/store.js` | Open timeline, saved library, undo/redo |
| `js/app.js` | Rendering and interaction |

1. **World.** The premise is mined for proper nouns (which become names) and
   motifs (which surface in the prose). A phonetic palette is chosen per world,
   so invented names sound like they share a language.
2. **Arc.** Events are distributed across seven acts — origins, expansion,
   fracture, crisis, cataclysm, aftermath, legacy — with later acts given more
   room and tighter spacing, because that is where consequences come due.
3. **Beats.** Each beat declares the cast it needs (`faction:alive`,
   `artifact:hidden`, `faction:atWarWith:A`), what must already be true, and what
   it changes. A war can only be declared between parties who have already
   fallen out; a treaty needs a war to end.
4. **State.** Effects update entity statuses, relationships and ownership. The
   whole state can be replayed from a saved timeline, which is what makes
   extending, expanding and re-rolling an existing chronicle coherent — a
   continuation inherits every grudge.

Beats bias toward entities already in play, so a chronicle keeps its
through-lines, and are weighted down after use so the same beat does not
dominate.

## Editing

- **Continue forward / Earlier history** — extend at either end. Continuations
  pick up unresolved threads; prehistory is generated without reaching forward
  for entities that do not exist yet.
- **Expand** — fill the gap after an event with smaller connecting events.
- **Re-roll** — rewrite one event against the world as it stood at that moment.
- **Branch** — fork an alternate history from any event. The original stays in
  your library.
- **Edit** — title, account, date, era, tags, weight, and which entities are
  involved. Drag the handle to reorder.
- **Pin** — protect an event from re-rolls.

Weight (1–5) drives the size of the node on the spine and feeds the importance
filter, so you can collapse a long chronicle down to its turning points.

Everything is undoable (`Ctrl/Cmd+Z`, `Ctrl/Cmd+Shift+Z`). Timelines save to
`localStorage` automatically; **Export** writes JSON (re-importable) or Markdown
(for reading), and the print stylesheet drops the chrome.

## Adding a genre

Add an entry to `GENRES` in `js/lexicon.js`. Every genre supplies the same word
banks (`group`, `role`, `placeKind`, `artifactKind`, `conflict`, `discovery`,
`collapse`, `ruin`, `force`, `omen`, `adjective`), a time scale, and a list of
phonetic palettes. No beat is genre-specific, so a new genre works with the
whole beat library immediately.

Adding a beat means appending to `BEATS` in `js/beats.js` — declare `acts`,
`cast`, `tags`, `importance`, and a `title`/`body` pair. Beats that call
`c.created` should also set `creates` to the entity kind to mint.

## Note on the content

Everything the app produces is fiction. Names, dates, factions and events are
invented and do not describe any real person, place or event.
